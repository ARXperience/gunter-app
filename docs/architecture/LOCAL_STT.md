# STT local experimental — Moonshine Spanish Small Streaming

Estado: **APPROVED_FOR_TRANSCRIPTION_ONLY**. Esta integración no autoriza ejecutar acciones de voz automáticamente. Se construyó en `feature/gunter-local-stt-moonshine` desde `d8144c0d894775e22627f3c59002fa1615766734`; `main` no se modifica.

## Runtime y modelo

- Runtime Windows x64 nativo: sidecar C++ basado en el ejemplo oficial Moonshine Voice 0.1.5, ONNX Runtime y `ffmpeg-static@5.3.0` para normalizar una copia temporal a PCM16 mono 16 kHz. El equipo del usuario **no necesita Python**. La opción oficial WASM 0.1.5 no abrió este checkpoint dividido en `frontend.model.ort`/`frontend.weights.ort`, por lo que no se adoptó.
- Modelo fijo `ModelArch.SMALL_STREAMING = 4`, `small-streaming-es/quantized_26_08_24`, ocho archivos/121 800 392 bytes. Hashes completos y hash del runtime en [manifest](../../server/models/moonshine-small-streaming-es.json). No se descargan ni versionan pesos.
- Configurar la ruta absoluta del modelo mediante `GUNTER_LOCAL_STT_MODEL_DIR` o `data/local-stt.json` (`{"modelDir":"D:\\ruta\\al\\modelo"}`). El manifest comprueba tamaño y SHA-256 antes de transcribir. `stt.local` permanece **off** por defecto.
- Binarios de runtime: `transcriber.exe` y `onnxruntime.dll` en el directorio definido por `GUNTER_LOCAL_STT_RUNTIME_DIR` o `runtimeDir` en `data/local-stt.json` (por defecto `native/moonshine/` para desarrollo). El fuente de adaptación está en `native/moonshine/transcriber.cpp`. **Los binarios tampoco se versionan**: deben instalarse por un proceso de build/instalador que preserve los hashes del manifest. No se incluyen datasets ni audios.
- **Licencias:** streaming STT se publica como MIT, pero sigue `PACKAGING_LICENSE_WARNING_PENDING_VENDOR_CLARIFICATION` por el aviso genérico no comercial del paquete Windows 0.1.5. Además, el binario `ffmpeg-static` instalado anuncia GPL-3.0-or-later. La distribución comercial de este paquete completo **no está aprobada** hasta revisión de cumplimiento y aclaración del proveedor. Esta rama es experimental/local.

## Enrutamiento y seguridad

`GunterSTT` sigue siendo la fachada única y `/api/transcribe` el endpoint único. AUTO/CLOUD conservan el proveedor cloud actual; LOCAL y LOCAL_ONLY usan únicamente Moonshine cuando `stt.local` está activado. Si faltan modelo, runtime o flag, responden `LOCAL_STT_NOT_INSTALLED`/`LOCAL_STT_UNAVAILABLE`, nunca hacen fallback cloud. Cambiar a AUTO/CLOUD o desactivar `stt.local` restaura el flujo anterior sin migrar datos.

El botón **Hablar** usa captura pulsar/volver a pulsar en LOCAL/LOCAL_ONLY: `MediaRecorder` → `GunterSTT` → servidor → streaming Moonshine con VAD → texto → turno del asistente marcado `inputSource: voice`. La escucha continua por Web Speech permanece separada y se bloquea en LOCAL/LOCAL_ONLY porque el navegador podría usar un servicio remoto; Moonshine no se emplea como wake-word detector. Archivos grabados, chunks de reunión, vault y recovery ya pasan por la misma fachada; el original no se altera. Cada petición admite solo MIME de audio ya usado por Gunter, 30 MiB y 120 s máximos, conversión en carpeta temporal aleatoria, timeout y concurrencia de una inferencia por proceso, con limpieza tras éxito/error/cancelación.

Inventario global: **MIGRATED** `js/transcription-service.js` (chunks/orden/IndexedDB), `js/audio-vault.js` (archivos), `js/controllers/session-recovery.js` (reintentos), el botón Hablar y los formularios de reunión que usan esos servicios. Todos terminan en `GunterSTT`/`/api/transcribe`; el fallback de fetch directo de chunks se eliminó. **LEGACY_INTENTIONAL** `wake-word-service.js` y el feedback en vivo de `transcription-service.js` usan Web Speech solo en AUTO/CLOUD; se deshabilitan antes de escuchar en LOCAL/LOCAL_ONLY. `js/ai-service.js` conserva Web Speech legado, sin instanciaciones en las páginas actuales. **FALLBACK**: texto previo de chunks recuperados si su reintento falla, nunca fallback cloud. No se encontró un consumidor STT activo sin el gate del servidor.

Una transcripción de voz que proponga una herramienta con efecto requiere confirmación explícita **por escrito o en pantalla**. El texto reconocido aparece junto a la propuesta; un «sí» transcrito no autoriza una acción pendiente. Las consultas de solo lectura no requieren confirmar solo por venir de voz. LocalBrain propone; el registro de herramientas y Permission Gate deciden. Las rutas heredadas que no conservan origen de voz se omiten o se cierran en fallo.

## Validación y límites

- Mini-gate nativo antes de conectar: 5 audios humanos de lectura, 3 órdenes humanas, silencio/ruido bajo/moderado/micrófono inactivo; 6/8 textos exactos al baseline previo (dos variaciones menores), 0/4 falsos positivos VAD. El corpus y las muestras permanecen fuera de Git.
- Medición integrada en este Ryzen 5 5500U/Windows CPU: un clip humano de 23,76 s tardó 19,96 s sin monitor (RTF 0,84); con muestreo, 19,84 s, pico de working set observado 248 MiB y 156,23 s de CPU de proceso acumulados (~7,9 núcleos lógicos durante la ejecución; muestreo aproximado). La misma muestra vía wrapper Python oficial, repetida inmediatamente en el mismo equipo, tardó 19,27 s, así que la diferencia contemporánea del sidecar fue ~3,6 %. El benchmark histórico de esa muestra había marcado 13,53 s; esa variación temporal afectó también al wrapper, no se atribuye al sidecar. Estas cifras no predicen latencia móvil ni carga sostenida/concurrente.
- Pruebas reproducibles: `npm run test:local-stt`; con `GUNTER_LOCAL_STT_MODEL_DIR` y `GUNTER_LOCAL_STT_TEST_AUDIO` apuntando fuera del repo, `npm run test:local-stt:live` y `npm run test:local-stt:offline`. La segunda bloquea `fetch` externo y conecta audio → Moonshine → Ministral → texto, no acciones.
- Se conserva `USER_VOICE_PENDING` y `HUMAN_NEGATION_COMMANDS_PENDING`. La transcripción real del usuario, órdenes negativas humanas, micrófono/dispositivo físico, Android/iOS y empaquetado legal siguen sin validar. No afirmar que el modelo preserva todas las negaciones ni que una intención reconocida es autorización.
